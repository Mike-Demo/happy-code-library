# Architecture

## Codebase layout

```text
src/
  webawesome/          THE DESIGN SYSTEM — everything consumers receive
    index.ts           barrel: wrappers, loader, patterns, theme editor, CDN URLs
    setup.tsx          WebAwesomeLoader — client-side element registration
    cdn.ts             version-pinned CDN URLs + idempotent CDN loader
    theme.css          theme entry (imports tokens.css + brand.css only)
    tokens.css         local snapshot of Web Awesome design tokens
    brand.css          brand overrides written by the theme editor
    types.d.ts         JSX intrinsic types for the custom elements
    react/             70 typed React wrappers, one file per element
    patterns/          SiteFooter, LicensesPage, HCaptcha (+ patterns.css)
    theme-editor/      tokens model, live-override hook, editor panel + CSS
    theme-editor.functions.ts / theme-editor-write.server.ts
    ssr/render.server.ts      opt-in server render helper
    vendor/            generated self-contained element bundles
  showcase/            PREVIEW-ONLY pages and sections (excluded via .dsignore)
  routes/              file-based routes (nine public + two editor-only)
  components/mockups/  canvas mockup scratch space
  assets/logos/        brand mark
  index.ts             root barrel — re-exports ./webawesome
  router.tsx           router + QueryClient factory
scripts/
  build-vendor.ts      regenerates the vendor bundles from the npm upstream
  vendor-entry*.js     bundle entry points (normal + SSR/hydration)
  copy-static-output.mjs   post-build static output normalizer
public/                favicon.png, robots.txt, sitemap.xml, _redirects, demos
```

The split that matters: **`src/webawesome/` is the library**, `src/showcase/`
and `src/routes/` are the preview app. `.dsignore` excludes `src/showcase/**`,
and the platform defaults already exclude `src/routes/`, so consumers who attach
this design system receive only the library folder and its assets.

## Design decisions

**File-based routing.** Routes live in `src/routes/`; `src/routeTree.gen.ts` is
generated — never edit it. Each route's `createFileRoute("...")` string must
match its filename mapping. Every public route declares its own `head()` with a
unique title, description and Open Graph tags; `__root.tsx` holds only shared
meta plus the stylesheet and favicon links.

**Providers-only root.** `src/routes/__root.tsx` renders just
`QueryClientProvider` + `<Outlet />`. No chrome lives there, because the two
editor-only preview routes (`/__mockup/...`, `/__component/...`) render inside
the root and any header or footer would leak into every preview frame.

**Element registration inside routed content.** `WebAwesomeLoader` is mounted in
the showcase shell, not in the root component. Registering custom elements above
the lazy routes caused hydration-mismatch warnings, because elements upgraded
before the route's SSR markup hydrated.

**Styling via tokens, never raw values.** Components consume Web Awesome CSS
custom properties. `theme.css` is the single import a consumer needs; brand
overrides go in `brand.css` (generated by the theme editor), and `tokens.css`
holds a local snapshot so token extraction works offline.

**Remote CSS loads as `<link>`, not `@import`.** The three remote stylesheets
(Web Awesome base/theme/utilities, Font Awesome, the anti-FOUCE `fouce.css`) are
linked from the document head using the pinned URLs exported by `cdn.ts`
(`WEB_AWESOME_STYLE_URLS`, `WEB_AWESOME_FOUCE_STYLE_URL`). A remote `@import`
inside `theme.css` breaks consumer CSS pipelines — Tailwind v4's Lightning CSS
resolves `@import` from the filesystem.

**Client vs server boundaries.** The site is static; there is no backend. The one
server touchpoint is the theme editor's "Save as default", implemented as a
server function (`theme-editor.functions.ts`) delegating to a `.server.ts` module
that refuses to run when `NODE_ENV === "production"`, validates input and caps
the payload. `ssr/render.server.ts` is deliberately *not* exported from the
barrel: it needs npm packages at runtime and must stay out of browser bundles.

**URL search params as state.** Browsable state that should survive reload and
sharing lives in the address bar — most visibly the icon page's search term
(`/icons?q=star`). Ephemeral UI state (open panels, hover) stays in React state;
theme overrides persist in `localStorage` under `wa-theme-overrides`.

**Data fetching.** TanStack Query is wired up (loader `ensureQueryData` +
`useSuspenseQuery` where a route needs data). The `QueryClient` is created per
request in `src/router.tsx`, never as a module singleton.

**Local, no-install distribution.** Web Awesome and Font Awesome are
`devDependencies` — build inputs only. The vendor bundle and the pinned CDN
stylesheets mean consuming projects install nothing. This is intentional: moving
them to runtime `dependencies` and declaring `upstream_package` would reclassify
the system as npm-backed, which requires an Enterprise plan. Audit suggestions to
do so are knowingly declined.

## Gotchas and lessons learned

- **Font Awesome icon path must be pinned to 7.3.1**, set inside the vendor
  bundle *before* any element registers. Web Awesome hardcodes 7.3.0, and
  requesting newer icons from the wrong version returns 403.
- **No direct jsDelivr JS imports** — the published files use bare specifiers.
  `esm.sh` also failed: it caused duplicate element registration. Hence the
  locally generated vendor bundle.
- **Prerender hangs without a timer guard.** Query cache timers armed during the
  prerender render keep the build process alive after every page is written.
  `src/router.tsx` installs an unref'd `timeoutManager` provider guarded by
  `process.env.TSS_PRERENDERING === "true"`.
- **No Cloudflare Worker entrypoint may exist in the repo.** A leftover
  `wrangler.jsonc` (and `@cloudflare/vite-plugin`) makes the static host refuse
  the build outright with "Cloudflare Worker entrypoints are not converted".
- **Never set `nitro: { preset: "static" }`** — it breaks this build with
  `rolldownOptions.input should not be an html file`. Prerendering is configured
  through `tanstackStart.pages` + `prerender` instead.
- **`autoStaticPathsDiscovery: false`** keeps the editor-only preview routes out
  of the prerender pass; they are also disallowed in `robots.txt`.
- **Anti-FOUCE:** apply the `wa-cloak` class to regions containing not-yet-upgraded
  custom elements. For opt-in server rendering, the `html[data-wa-ssr]` rule
  handles the equivalent flash.
- **Shadow DOM breaks naive queries.** Test helpers and search code must pierce
  shadow roots to find element internals.
- **`window.hcaptcha` collides** when a page loads the script more than once —
  the pattern guards detection and polls asynchronously instead of assuming
  ownership. Verification happens server-side at
  `https://api.hcaptcha.com/siteverify`; secret keys never appear client-side.
- **Regenerating wrappers/bundles** is a script, not hand-work:
  `bun scripts/build-vendor.ts` after bumping the upstream version pins.
